# Weekly Status Report: Textplorer
**Date:** February 15th, 2026  
**Project Phase:** Parser Development & Documentation

## 1. Team Report

**Status Update for TA:** We made significant progress on documentation and began implementing the core parser functionality. We now have comprehensive developer and user guides, established our testing framework, and have a basic working version of the text-to-level parser.

### 1.1 Goals from Last Week
* **Complete Menu Pages:** Create individual pages for each menu option (Play page, Upload page, Settings/Instructions page). Link them properly from the main menu. *(Almost Done)*
* **Text File Parser Implementation:** Begin developing the core parser functionality that will convert .txt files into playable level data. Start with basic string parsing and character-to-tile mapping. *(Almost Done)*
* **Test File Creation:** Create sample .txt level files to use for testing the parser once it's implemented. *(Completed)*

### 1.2 Progress and Issues
* **Progress:**
  * **Developer Guidelines Created:** Completed comprehensive developer documentation covering how to obtain source code, directory structure, building the software, testing procedures, adding new tests, and building releases.
  * **User Documentation Completed:** Finished user-facing documentation to help players understand how to play the game and create their own levels.
  * **Test Cases Infrastructure:** Created the test_cases folder and researched how to write and structure test files. Understand the testing framework and are ready to begin writing actual tests.
  * **Basic Parser Implemented:** Successfully created a very simple text file to level parser that can read .txt files and begin converting them to level data.
  * **Sample Levels Created:** Built simple example .txt level files to test the parser functionality and demonstrate the level creation format.
  
* **What Worked:** The documentation effort went smoothly and will save significant time onboarding new contributors. The basic parser proof-of-concept works, confirming our approach is viable.

* **What We Learned:** We learned that designing the character-to-tile mapping system requires careful consideration of which symbols are intuitive for users. We also discovered that parsing text files is straightforward, but translating that into actual playable game tiles with proper collision and physics is more complex.

* **Trouble/Stuck:** We're still working on the gameplay logic that connects the parsed level data to actual playable tiles on screen. The character-to-tile concept needs more refinement - we need to finalize which keyboard symbols map to which game objects and implement the rendering system. The parser currently reads files but doesn't yet create fully interactive game levels.

### 1.3 Goals for Next Week
* **Complete Character-to-Tile Mapping:** Finalize the legend of which symbols represent which game objects (walls, platforms, hazards, player start, goal). Implement the rendering system that converts parsed data into visual game elements. *Estimate: 3 days*
* **Begin Physics Implementation:** Start implementing basic player movement and collision detection using Phaser's physics engine. *Estimate: 3 days*
* **Write Initial Test Cases:** Create the first set of unit tests for the parser, testing valid inputs, invalid inputs, and edge cases. *Estimate: 2 days*
* **Expand Sample Levels:** Create more complex example levels to test different gameplay scenarios and parser capabilities. *Estimate: 1 day*
