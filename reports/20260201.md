# Weekly Status Report: Textplorer
**Date:** February 1, 2026  
**Project Phase:** Architecture Selection & Initial Prototyping

---

## 1. Team Report

**Status Update for TA:** This week, the team moved from general exploration into project architecture. We have officially locked in our hosting platform and finalized the structural design of the application. 

### 1.1 Goals from Last Week
* **Environment Setup:** Initialize the GitHub repository with a basic file structure. (**Completed**)
* **The "Hello World" Window:** Get a blank Phaser canvas to render in a web browser. (**Completed**)
* **Initial Legend Drafting:** Start mapping keyboard symbols to game objects. (**In Progress**)

### 1.2 Progress and Issues
* **Progress:** * **Architecture Finalized:** Decided on a Component-Based architecture within Phaser to handle different game entities (player, walls, hazards).
    * **Hosting Selected:** After comparing Heroku and GitHub Pages, we chose **GitHub Pages** for its seamless integration with our repo and its efficiency in serving static assets.
    * **Initial Prototyping:** Started basic coding to test how Phaser handles sprite movement and how we might parse strings into game objects.
* **What Worked:** Finding that GitHub Pages provides a near-instant deployment pipeline for our Phaser builds, which will make iterative testing much faster.
* **What we Learned:** While Heroku offers more backend flexibility, GitHub Pages is significantly faster for a client-side game and avoids the "cold start" sleep issues of free-tier servers.
* **Trouble/Stuck:** We are still refining the logic for the "Text Parser." We need to ensure that the transition from a `.txt` file to a 2D array in JavaScript doesn't create performance issues during level loading.

### 1.3 Goals for Next Week
* **Asset Pipeline:** Create or source placeholder sprites for the "Legend" symbols (e.g., a block for `#`, a spike for `^`). **Estimate: 2 days**
* **Parser Foundation:** Write a JavaScript function that can take a hardcoded string and print it to the console as a formatted grid. **Estimate: 3 days**
* **Deployment Automation:** Set up a GitHub Action to automatically deploy the `main` branch to the live site. **Estimate: 1 day**
